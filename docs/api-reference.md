# API Reference

This service exposes a single HTTP interface bound to host `127.0.0.1` and port `3000` (`Source: server.js:L3-L4`, `Source: server.js:L12`). It is implemented as a single-file Node.js service that uses only the standard-library `http` module (`Source: server.js:L1`); the reference below documents the complete, observable request/response behavior of that interface.

The request handler that implements this behavior is **F-002 Uniform Request Handler**, the key functionality of the service. For the functionality-level description of F-002, see [`./functionality.md`](./functionality.md).

## Endpoint model

There is exactly **one catch-all endpoint**, served by a single request handler. The handler runs the same application code for every request it receives and never inspects the incoming request object (`Source: server.js:L6-L10`), so it does not branch on method or path. This uniformity is a property of the *application code*; Node's `http` module layers a small number of protocol-level behaviors on top of it, so the observable wire response is not literally identical for every HTTP method (see the **Method and protocol behavior** section below).

Concretely, the application code provides:

- **No routing** — there is no route table and no path-based dispatch (`Source: server.js:L6-L10`).
- **No path matching** — `/`, `/anything`, and `/a/b/c` all reach the same handler code (`Source: server.js:L6-L10`).
- **No method dispatch** — `GET`, `POST`, `PUT`, `DELETE`, and any other method all reach the same handler code, which never reads the request method (`Source: server.js:L6-L10`).

The handler is registered once via `http.createServer((req, res) => { ... })` and runs the same fixed logic for all traffic delivered to it through Node's `request` event (`Source: server.js:L6-L10`).

## Request handling

The request object (`req`) is received in the handler signature but is **never read** (`Source: server.js:L6`). No request method, path, query string, request header, or request body is parsed or used anywhere in the handler (`Source: server.js:L6-L10`).

Consequently, the **shape of an ordinary request has no effect on what the application code does** (`Source: server.js:L6-L10`). As a scoped runtime observation on Node.js v22.23.1 (Windows), `GET /` and `POST /anything/else?q=1` sent with a request body returned byte-identical responses, confirming that the handler does not branch on method, path, query string, or body.

## Response contract

Every ordinary request delivered to the handler receives the following fixed response. The **Origin** column distinguishes values set by the application source from values generated by Node's `http` module:

| Aspect | Value | Origin |
|--------|-------|--------|
| Status code | `200` | Set in source (`Source: server.js:L7`) |
| Reason phrase | `OK` | Conventional HTTP reason phrase for status `200`, generated by Node's `http` module — not set in the source |
| `Content-Type` | `text/plain` | Set in source (`Source: server.js:L8`) |
| Response body | `Hello, World!` + one LF byte (`0x0A`) — 14 bytes total | Set in source (`Source: server.js:L9`) |

The response body is the 13 ASCII characters `Hello, World!` followed by a single line-feed byte (`\n`, `0x0A`), for **14 bytes** total; the trailing `\n` in the source string literal `'Hello, World!\n'` is one newline byte, not the two literal characters `\` and `n` (`Source: server.js:L9`).

This application-set contract is produced for every ordinary request delivered to the handler through Node's `request` event, independent of method, path, headers, or body, because the handler never inspects `req` (`Source: server.js:L6-L10`). Two protocol-level exceptions applied by Node's `http` module (`HEAD` and `CONNECT`) are documented in the **Method and protocol behavior** section below.

## Response headers

The only header set by the application code is `Content-Type: text/plain` (`Source: server.js:L8`); it is the sole header-level application invariant. Every other header on the response is generated by Node's `http` module rather than by `server.js`, and its presence, value, ordering, and formatting can depend on the Node.js version, the negotiated HTTP protocol version, the request method, and the request's own headers.

The table below is a **representative observation**, not a source-derived contract. It records the headers returned for the exact request `GET / HTTP/1.1` shown in the **Example** section below, captured at runtime on **Node.js v22.23.1 (Windows)**. A different Node.js version, request method, or set of request headers can produce a different generated-header set, as noted beneath the table:

| Header | Observed value | Origin |
|--------|----------------|--------|
| `Content-Type` | `text/plain` | Application-set invariant (`Source: server.js:L8`) |
| `Date` | RFC 1123 GMT timestamp (regenerated per response) | Node `http` module; dynamic |
| `Connection` | `keep-alive` | Node `http` module; reflects connection negotiation with the client |
| `Keep-Alive` | `timeout=5` | Node `http` module; present only while the connection is kept alive |
| `Content-Length` | `14` | Node `http` module; equals the 14-byte body (`Source: server.js:L9`) for responses that carry the body |

> **Note.** Only `Content-Type: text/plain` (`Source: server.js:L8`) is guaranteed by the source. The generated headers vary with the runtime and the request:
> - **`Content-Length`** is present for responses that carry a body (for example `GET` and `POST`) and equals the body's byte length, `14` (`Source: server.js:L9`); it is **omitted for `HEAD`**, whose response carries no body (observed on Node.js v22.23.1, Windows).
> - **`Connection`** and **`Keep-Alive`** reflect connection negotiation: a request sent with `Connection: close` is answered with `Connection: close` and **no `Keep-Alive`** header (observed on Node.js v22.23.1, Windows).
> - **`Date`** is regenerated on every response.
> - The HTTP protocol version, header ordering, and exact default-header set can also differ across Node.js versions. Treat this table as representative of the tested environment, not as a cross-version guarantee.

## Method and protocol behavior

The application handler runs identical code for every request delivered to it through Node's `request` event, but Node's `http` module applies two protocol-level behaviors on top of that code, so the observable wire response is **not** literally identical for every HTTP method:

- **`HEAD`** — the handler runs exactly as it does for `GET` (status `200`, `Content-Type: text/plain`), but Node suppresses the response body in accordance with HTTP semantics, so a `HEAD` response carries **zero body bytes** and **omits `Content-Length`** (observed on Node.js v22.23.1, Windows). The application code is unchanged (`Source: server.js:L6-L10`); only body transmission differs.
- **`CONNECT`** — a `CONNECT` request is delivered by Node's `http` module through a separate `connect` event, not the normal `request` event, so it never reaches this handler. The source attaches no `connect` listener (complete-source inspection, `Source: server.js:L6-L10`), so a raw `CONNECT` receives **no response** (observed as zero response bytes on Node.js v22.23.1, Windows).

For all ordinary requests delivered through the `request` event — for example `GET`, `POST`, `PUT`, and `DELETE` — the handler applies the uniform response contract described above (`Source: server.js:L6-L10`).

## Example

The request and response below were captured at runtime on **Node.js v22.23.1 (Windows)**; the generated headers (`Date`, `Connection`, `Keep-Alive`, `Content-Length`) are representative of that environment, as described under **Response headers**.

Request:

```sh
curl -i http://127.0.0.1:3000/
```

Response:

```http
HTTP/1.1 200 OK
Content-Type: text/plain
Date: <dynamic RFC 1123 timestamp>
Connection: keep-alive
Keep-Alive: timeout=5
Content-Length: 14

Hello, World!
```

The blank line separates the headers from the body. The body is `Hello, World!` followed by a single trailing line-feed byte (`\n`, `0x0A`) — **14 bytes** total (`Source: server.js:L9`); that terminal newline is why the printed output breaks the line after `Hello, World!`.

Because the handler never inspects `req` (`Source: server.js:L6-L10`), the same application response contract — status `200`, `Content-Type: text/plain`, and the 14-byte body — is produced for any ordinary request regardless of method or path; for example, `curl -X POST http://127.0.0.1:3000/anything` returns the same status, `Content-Type`, and body. The Node-generated headers (`Date`, `Connection`, `Keep-Alive`, `Content-Length`) can still vary with the request and runtime, as described under **Response headers**, and the protocol-level exceptions for `HEAD` (no body) and `CONNECT` (not handled) are described under **Method and protocol behavior**. For the functionality-level description of this handler (F-002), see [`./functionality.md`](./functionality.md).
